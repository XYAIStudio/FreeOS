## 范围修正

用户明确要求：openXYOS 全部已实现的网页模块、功能和彼此逻辑关系，完整转化成 FreeOS「组织」的子模块，保持对应界面内容与操作能力，形成统一、便于使用的产品。

本要求取代 `org-merge-plan.md` 中「只迁 Open-12」「商业 App.tsx 不迁」「Chat 永久不迁」的范围限制。旧 Phase 0–5 是有限切片的工程记录，不代表全量融合完成。原有 Chat 的组织沟通功能必须纳入对应分析，是否复用宿主执行引擎不能成为丢弃功能的理由。

范围取 `App.tsx`、`OpenApp.tsx` 的并集，并继续追踪页面内部标签、详情、弹窗、设计器和未直接挂路由的组件。没有可执行实现的原始占位，单独记为原系统缺口，不伪称原功能或迁移完成。

## 一致性要求

每个子模块必须同时满足：

1. 页面字段、视图、筛选、统计、详情、内部标签、弹窗、导入导出与原有有效实现对应。
2. 原有操作连接真实 API 和持久化数据；重载和应用重启后可读取。
3. 组织、部门、员工、账号、任务等关联保持一致，不在不同页面维护互不相通的副本。
4. 保留角色权限与租户边界；统一登录不得以把所有用户映射为管理员替代。
5. 跨页跳转留在组织子模块，身份、语言、时区和返回路径一致。
6. 空态、失败、权限不足和未实现能力明确显示，不静默返回成功或样例数据。
7. 独立站与宿主共享页面来源；原页面仍是功能对照基准。
8. 原页面对照、真实交互、后端测试与最终安装版验收分别留证。

客户服务、电力交易等原路由也包含在盘点中，不因没有列在 Open-12 而自动排除。
