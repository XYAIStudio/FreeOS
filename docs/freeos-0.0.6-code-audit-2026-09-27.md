# FreeOS 0.0.6 代码审计与质检（2026-09-28）

审计基线为 PR #93 的 `f302486`，本轮在该分支完成组织启动、模块状态、Windows 窗口恢复、openXYOS 持久化和本机模型兼容修复。发布状态以 GitHub `v0.0.6` Release 与工作流结果为准。

## 已修复问题

| 优先级 | 问题 | 处理与验证 |
| --- | --- | --- |
| P1 | 组织页首次自动启动请求会被 React effect 清理取消，页面长期停在端口等待。 | 用 ref 管理单次启动；相关前端回归通过。 |
| P1 | 桌面宿主与 Python 组织启动器可能同时管理 openXYOS，造成端口与进程竞争。 | Python 检测桌面托管运行时并退出重复生命周期；单元测试通过。 |
| P1 | openXYOS 数据库直接覆写文件，读取也触发整库落盘。 | 改为临时文件原子替换；读取不再写盘；持久化测试通过。 |
| P1 | 集成版系统设置使用了错误的模块状态组件，开关不能实时更新侧栏。 | 接回集成模块管理；实际点击关闭/开启后侧栏即时变化，刷新后状态保持。 |
| P1 | Windows 窗口恢复后会收到隐藏操作产生的延迟关闭事件，再次被隐藏。 | 宿主标记并消费该关闭事件，托盘动作只执行显示；连续 10 轮“最小化→显示”均保持可见和焦点。 |
| P1 | `qwen2.5vl:3b` 可正常对话，但 Ollama OpenAI 端点拒绝 tools，通用重试最终显示 `stream_error`。 | 仅在服务端明确返回“不支持 tools”时去掉工具重试；直接接口复现与新增中间件测试通过。 |

## 验证门槛

- Windows 桌面：`go test ./...` 通过；Wails 开发 EXE 编译通过。
- openXYOS：数据库持久化、模块设置、类型检查、lint 和 FreeOS 集成构建通过。
- Dashboard：Vitest、TypeScript 类型检查和生产构建通过。
- 仓库门槛：`PYTHONUTF8=1 make all` 全绿，3,575 passed、114 skipped；Ruff 与 mypy（587 个源文件）通过。并行测试的 `DISPLAY` 前提已显式隔离。
- Windows 实机：组织一键测试登录成功；模块开关关闭、刷新保持、重新开启均通过；窗口恢复连续 10/10 通过。
- Windows amd64：完整便携包与 NSIS 安装器已重新生成，并包含最新 Dashboard、Python 运行时和 openXYOS 运行时。

## 已知非阻断项

- FastAPI OpenAPI 仍报告组织代理路由重复 Operation ID 警告，当前不影响接口调用，但后续应为代理方法生成唯一标识。
- Windows 目录被第三方进程长期锁定时，便携运行时覆盖恢复仍依赖系统释放文件句柄；安装前应退出旧版 FreeOS。

安装和升级步骤见 [FreeOS 0.0.6 安装指南](install-0.0.6.zh-CN.md)。
