# openXYOS 首发开源发布闸门

> 适用主体：北京雄元科技有限公司（XYOS 软件著作权、人机技术方法权利人）；注册圆形 Logo 的商标权利人为中国雄元集团有限公司。本文是首发前的内部执行规范，不替代律师对合同、商标和专利文件的审核。

## 轻量职责模型

无需设置独立部门。每次公开发布只需要两类动作：

1. **维护者执行**：完成代码、依赖、密钥、许可证和文档检查，并形成发布证据包。
2. **权利人确认**：由雄元科技指定负责人确认开源范围、品牌使用与专利边界；首次公开和重大条款变更交外部律师复核。

## 强制闸门

| 闸门 | 必须满足 | 失败时动作 |
| --- | --- | --- |
| 权属 | 代码作者、员工、外包、合作方的权属链可追溯 | 从发布候选中移除未确认部分 |
| 专利 | 人机技术方法或其他申请的公开边界、源码处置和文档处置均已完成书面决定 | 从发布候选移出相关代码、历史资料、测试、演示与构建产物 |
| 商标 | 注册 Logo、项目名称和待申请标识的使用符合 `TRADEMARKS.md` | 改名、去标识或取得书面许可 |
| 开源 | `LICENSE`、`NOTICE`、第三方许可证和贡献规则完整 | 补齐后再发布 |
| 安全 | `npm run verify:open-source`、测试、构建和人工敏感信息审查通过 | 修复或移除敏感内容 |
| 发布 | Git 标签、变更说明、依赖锁定、已知限制和安全报告入口齐全 | 不得标注为官方发布版 |

## 人机技术专利边界

Apache-2.0 的代码贡献可能附带必要的专利许可。因此，人机技术采用“通用能力可开放、专有方法及其旁证默认隔离”的策略。以下内容不得进入公共仓库，除非权利人和外部知识产权律师已完成专项书面复核：

- 专有方法的实现、接口、数据模型、状态规则、测试、种子数据、交互演示及其等价改写；
- 尚未提交申请的技术方案、实验数据、客户场景和性能指标；
- 能使外部人员复现、推导或验证专有方法的设计文档、历史研发资料、对比材料或构建产物。

默认策略：开放独立设计的通用接口、基础流程和可替换示例；将专有方法、企业治理策略包、托管服务连接器和客户交付工具保留在独立非公开仓库。改名、删注释或仅删除少量字段不构成合格隔离。

当前仓库的首发审查路径见 [人机源码公开边界](HUMAN_MACHINE_SOURCE_BOUNDARY.md)。

## 证据包

每个首发或正式版本在私有发布档案中保存：代码提交与标签、构建哈希、SBOM、扫描结果、第三方许可证清单、权属确认记录、专利边界确认、商标审批、变更说明和撤回/补丁记录。该档案不得提交到公共仓库。

许可证准入规则见 [开源许可证策略](OPEN_SOURCE_LICENSE_POLICY.md)，贡献协议与隐私声明在正式发布前须完成律师审核。
